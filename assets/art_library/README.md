# Live artwork library

This folder is the **source the game loads**, not a disconnected reference copy.
It gathers the generated scenes, characters, animation sheets, item sprites,
camp illustrations and painted UI, together with retained variants and fallbacks.
Existing source credits and provenance files remain beside their assets.

Open **[catalog.html](catalog.html)** locally in a browser to search filenames and
preview individual sprites, including atlas regions. **[manifest.json](manifest.json)**
lists sizes, atlas coordinates, known literal references and PNG override names.
Runtime-composed paths also use this library; the literal reference list alone
does not determine whether an image is used.

| Folder | Contents |
| --- | --- |
| `items/` | All 87 current item illustrations, empty-slot symbols and legacy SVG fallbacks |
| `items/sheets/` | Four original generated icon sheets; `layout.json` identifies each tile |
| `camp/` | Keep Watch, Protective Rite, Ready Weapons, Study the Route and Rest |

| `appearance/` | Character costume variants and atlas region definitions |
| `equipment/` | Equipment appearance variants and atlas region definitions |
| `presentation/` | Layered scenery, settlement interiors/attendants, effects and UI |
| `warden_outfits/` | Complete original and Ashen Wolf costume atlases and views |
| `skills/` | Combat ability artwork, atlas resources and SVG fallback symbols |

## Replace one item with your drawing

1. Find the stable item ID in the catalog. For example, `healing_potion`.
2. Export your drawing as a **transparent PNG**, preferably **256×256** or **512×512**.
   Keep the object centered with clear outer margins; do not bake in a rarity border,
   name, quantity or background. These are rendered by the UI.
3. Save it as **`items/healing_potion.png`** in this folder.
4. Reopen/reimport the project in Godot, then rebuild the inventory or restart the
   game. That PNG automatically takes priority over `healing_potion.tres` and its
   legacy SVG. No gameplay code or item ID changes are required.

The `.tres` files are small atlas definitions, not images to paint over. Do not
replace the whole sheet to update one item. A same-name PNG is the simplest option.
Deleting that override restores the generated atlas image. The rule also applies
to cherished/renamed item instances: they resolve through their original base ID.

## Replace camp or ability artwork

Use `camp/watch.png`, `camp/ward.png`, `camp/sharpen.png`, `camp/scout.png` or
`camp/rest.png`. PNGs override the corresponding atlas definitions. The same rule
applies to individual combat skills in `skills/`, such as `skills/wd_guard.png`.
Buttons, effect descriptions, point costs and disabled/prepared states stay in code.

## Replace backgrounds, characters or animation sheets

Overwrite the matching PNG in `generated/`, `appearance/`, `equipment/` or
`presentation/`, preserving its filename. Match the original canvas dimensions,
transparency, ground line and alignment. Keep backgrounds opaque, cutout characters
transparent, and layered scenery aligned with the companion layers.

For an atlas/sprite sheet, preserve **every existing frame's rectangle and order**.
The manifest shows `.tres` regions; additional animation regions are defined in
the nearby `regions.gd` files and scripts such as `scripts/combat_pose_regions.gd`.
Changing frame positions or sizes requires updating those definitions too.
For individual cropped portraits, edit the referenced sheet region or change its
`.tres` atlas to a new texture. Do not rename the source image without updating its
resource references.

The settlement hover samples the town painting directly. Repainting its buildings
in different positions also requires retracing `BUILDING_OUTLINES` in
`scenes/hub/settlement.gd`; a lighting/material repaint with unchanged geometry
keeps the current registration.

## Keeping the index current

Run `python3 tools/index_art_library.py` after adding/replacing sources. It reads
image headers and resource text, generates the manifest/catalog, and never changes
image pixels. Godot import metadata is generated by the editor; do not paint or
hand-edit `.import` files.

The new item/camp sprites were generated with OpenAI's image tools on 2026-10-12.
All four sheets contain 24 tiles of 256×256 pixels, with the original sheet pixels
preserved. Existing project art and its original credits remain separate in their
source folders; moving it here does not change its provenance or license.

Full-screen strongbox event art is `generated/story_strongbox.png`.
The library excludes abandoned animation experiments and obsolete review assets.
